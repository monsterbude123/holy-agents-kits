# review-protocol · 技能评审协议（从实战漏网案例提炼）

> 缘起：codebase-slimming 入库评审（2026-11-26）实测提炼。
> **反形式主义总纲**：本协议每个检查项必须能指认它拦下（或本可拦下）的**历史漏网案例**；
> 指认不出案例的检查项不得加入；案例绝迹的检查项应退役。评审不是走过清单，是找「照抄会出事的点」。

## 一、评审三层：机器 → 对账 → 人眼

**第 1 层：机器门禁先行**（`validate_skill.py --all` + `npm test` 全家桶）。
结构问题（行数、frontmatter、引用完整性、反馈入口、README 门面）不占人脑，机器说了算。

**第 2 层：事实断言逐条对账**——skill 里每条命令、默认值、工具名、版本号、比例数字都要挂证据，三选一：
- **官方文档对账**：命令参数语义、工具默认值、版本是否存在。
  - 案例A：dpdm 死代码命令把「入口/候选全集」写反——照抄会**静默输出死代码=0 的假数据**，是 P0 而非笔误；
  - 案例B：cloc「默认 1MB 截断」实为官方默认 100MB；
  - 案例C：jscpd 门禁命令用默认 exact 模式，与同一 skill 里「token 工具抓不到改名克隆」的告诫自相矛盾。
- **本地复现**：行为类断言（案例：`git ls-files` 中文路径八进制转义，临时仓 5 分钟实测定案）。
- **环境枚举**：工具名先枚举**本机实际配置的 MCP server / CLI**，再查官方文档。
  - ⚠️ 反例教训（评审者自己的错）：判 `ide_find_references`「官方无此名=杜撰」，后来本机 idea-index server 连上后证明真实存在。**官方文档没有 ≠ 不存在，可能只是私有实现**；反过来也一样——私有 server 上的工具名出了本机就断，写进 description/铁律前要问「换台机器还成立吗」。

**第 3 层：人眼判断**（无门禁可代）：
- **照抄模拟**：把每条命令当成将被 agent 在陌生机器原样执行的东西审——裸 glob 开没开引号、PATH 里有没有这个解释器（案例：本仓 harness 调裸 `python`，本机只有 anaconda 路径）；
- **内部自洽**：同一 skill 前后是否互相打脸（案例C 属于此类）；
- **内容卫生**：项目专名/业务代号/内部架构叙事进公开仓 = 泄密风险（案例：novel-promotion、老短剧、画布拓扑进了 kit 公开仓）→ 处方：主干通用化 + 案例外迁 `case-study.md` 并脱敏，**数字保留、专名脱敏**（数字不涉密，专名才涉密）；
- **先验标注**：单项目比例数字（死代码 1~3%、tests 占比等）必须标注「单项目实测先验，仅作量级参考」，不得写成普适规律。

## 二、失败形状分级（按后果分，不按词面）

| 级 | 形状 | 判据 | 案例 |
|---|---|---|---|
| P0 | **静默错误** | 照抄不报错，但产出假数据/假结论 | dpdm 反转、wc 汇总行双计（56万→109万） |
| P1 | **会断** | 门禁红、跨机器/跨环境失效、仓外炸生产 | 缺反馈入口卡 CI、私有工具名出不了本机、拔 API 路由不看仓外消费方 |
| P2 | **债** | 不炸但持续腐蚀：重复拷贝、漂移、歧义 | 同一判断 3~4 份拷贝、README「十二个」vs 实际 16 个漂移两个发版周期、文不对题的文件名 |

## 三、评审者自查（评审员自己也是案例来源）

- **先查已有文档再报「新发现」**：案例——anaconda python 的 PATH 陷阱早已写在 `environments.md`，评审发版时重新踩了一遍才想起来。评审前先 grep 仓库现成结论。
- **产出自检**：交出的每条 P0/P1 必须自带证据指针（文档 URL / 复现命令 / 门禁输出）；给不出指针的降级为「印象，待验证」并明说。

## 四、门禁分工表（机器管结构，人管语义）

| 检查 | 归属 | 状态 |
|---|---|---|
| 行数 / frontmatter / 引用完整性 / 反馈入口 | `validate_skill.py` | 已有 |
| README 门面 5 面对账（表格/mindmap/详解/仓库结构/标题计数） | `scripts/check-readme-sync.mjs` | 2026-11-26 新增，红测验证能拦 12/16 漂移 |
| 命令语义 / 工具默认值 / 版本真伪 | 联网对账（人，第 2 层） | 无门禁可代——别试图用 grep 冒充 |
| 专名脱敏 / 先验标注 / 照抄模拟 | 人（第 3 层） | 无门禁可代 |
| 发版三通道（npm / GitHub / 本机全局） | kit-release 7 步 | 已有 |
