# 环境差异与降级路径

同一个技能在不同运行环境里能做的事不一样。**动手前先确认自己在哪个环境**，
否则会写出跑不起来的流程。

---

## 1 本仓默认环境

| 项 | 事实 |
|---|---|
| 运行时 | ZCode（兼容 Claude Code 的 agent 运行时），有子代理（`Agent` 工具） |
| `claude` CLI | **没有**。`scripts/run_eval.py` / `run_loop.py` / `improve_description.py` 依赖 `claude -p`，本机跑不了 |
| `present_files` 工具 | **没有**。要交付文件就直接把绝对路径告诉用户 |
| Python | Windows 上 `python` 未必在 PATH。依次试 `python` → `python3` → `py -3`；本机 anaconda 在 `C:/Users/admin/anaconda3/python.exe` |
| 技能安装路径 | `skills/` = **要交付出去的技能**；`.agents/skills/` = 研发期用的元技能（如本技能） |
| 浏览器 | 有 MCP 浏览器工具，但不一定有图形界面；评测视图优先用 `--static` 输出独立 HTML |

### 由此产生的三条硬规矩

1. **不要把 `claude -p` 写进必做流程。** 描述优化、触发率评测在本机走
   `references/description-optimization.md` 里的**降级路径**（人工判定 + 改写 + 复核）。
2. **不要调用 `present_files`。** 打包完直接给 `.skill` 文件的路径。
3. **技能别放错目录。** 新技能放 `skills/`；研发工具放 `.agents/skills/`。
   放错了会被当成交付物发出去。
4. **全局 vs 项目按用途分流。** 跨项目、跨宿主要用的技能进 `skills/` 走发版（npx 同步到各宿主的全局技能目录）；
   只服务本仓研发流程的元技能放 `.agents/skills/`，不进发版。
5. **别改宿主本地副本。** 各宿主全局目录里的技能是发版的下游，本地改动会被下次 npx 同步覆盖；
   要改就回仓库改源头，再发版。

### 路径示例

```bash
# 交付出去的技能
skills/work-with-ai-gateway/SKILL.md

# 研发期元技能（本技能自己）
.agents/skills/skill-creator-v2/SKILL.md
```

## 2 Claude Code

能力最全：子代理、浏览器、后台任务、`claude` CLI 都在。
`references/evaluating.md` 的完整流程（并行发起带技能 / 基线运行、评分子代理、
`generate_review.py` 评审视图）在 Claude Code 里原样可用。

---

## 3 Claude.ai

没有子代理，部分机制要换：

- **跑用例**：没有并行子代理，就自己读 SKILL.md 然后照着做，一个一个来。
  严谨度不如独立子代理（写技能的人和执行的人是同一个），但作为健康检查够用，
  人工评审这一环本来就在补偿。
  **跳过基线运行**，直接用技能完成任务。
- **评审**：没有浏览器就跳过评审视图，直接在对话里呈现结果。
  产出是用户要的文件（.docx / .xlsx 等）就存到文件系统，告诉用户路径让他下载。
  逐个用例展示提示词与产出，直接问「这样看行不行？哪里要改？」
- **benchmark**：跳过。它依赖基线对比，没有子代理就没有意义，专注定性反馈。
- **描述优化**：需要 `claude` CLI，跳过。
- **盲测对比**：需要子代理，跳过。
- **打包**：`package_skill.py` 只要 Python 和文件系统，照常可用。
- **改造已有技能**：保留原 `name` 与目录名（别改成 `xxx-v2`）；
  装好的技能目录可能是只读的，先复制到可写位置再改。

## 4 Cowork

- 有子代理，主流程（并行跑用例、跑基线、评分）照常。
  遇到严重超时可以改成串行跑。
- 没有浏览器或显示设备：出评审视图时用 `--static <output_path>` 输出独立 HTML，
  给用户一个能点开的链接。
- **评审视图必须在你自己评估之前生成**——先把结果推到人眼前，再自己动手改技能。
  别自己闷头看输出。
- 反馈方式不同：没有常驻服务，视图里的「Submit All Reviews」会**下载** `feedback.json`，
  你从下载目录读（可能需要先申请访问权限）。
- 打包正常。描述优化依赖 `claude -p`，若 Cowork 里可用则照常，否则走降级路径。

---

## 5 降级速查

| 想做的事 | 环境缺什么 | 降级方案 |
|---|---|---|
| 触发率评测 | `claude` CLI | 人工判定 20 条查询，逐条记录漏触 / 过触 |
| 描述优化 | `claude` CLI | 人工改写 + 复核对比表 |
| 并行跑用例 | 子代理 | 自己在当前会话里串行执行 |
| 评审视图 | 浏览器 / 显示设备 | `--static <path>` 输出独立 HTML |
| 基线对比 | 子代理 | 跳过基线，只做定性评审 |
| 交付文件 | `present_files` | 直接给出文件绝对路径 |
