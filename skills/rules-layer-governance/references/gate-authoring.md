# 门禁下沉 —— 把 prose 规则变成机器抓手

**下沉的目标不是「少写文档」，是让违规在提交前就被拦住**。
判据：一条规则能不能机器验证？不能就别硬下沉 —— 硬凑出来的门禁会制造「假安全感」，
比没有门禁更糟（人以为有人管了）。

---

## 一、该不该下沉

| 能下沉 | 不能下沉 |
| --- | --- |
| 计数型禁令（禁 console.log / 禁 100vh / 禁某命名法） | 语义判断（代码该怎么设计） |
| 文件存在性 / 路径引用可解析性 | 「要写得可读」这类质量倾向 |
| 配对型约束（A 改了 B 必须同批） | 权衡取舍（「该用 X 还是 Y」） |
| 已有的检查脚本包一层 | 流程顺序（谁先谁后） |

---

## 二、脚本骨架

复制 `templates/gate-script.sh`，逐项替换 `<N>` 与 `RULE`。骨架的六段结构固定：

```bash
#!/usr/bin/env bash
# scripts/gates/<N>.sh — 门禁:<一句话标题>
# 来源:<审计报告编号>(原位置 <规则文件 §小节>)
# 规则原文:<规则全文>
# 口径:<检查什么> ≤ 基线 <M>(<日期> 实测,<ratchet 型才写>)
set -u
ROOT="$(cd "$(dirname "$0")/../.." && pwd)"; cd "$ROOT" || exit 2   # ① 自身定位
RULE='<规则全文>'                                                     # ② 违规时原样回显
if [ -f scripts/gates/EXCEPTIONS.md ] && \
   grep -qE "^gate-<N>([^0-9]|$)" scripts/gates/EXCEPTIONS.md 2>/dev/null; then
  echo "SKIP gate-<N>：已在 scripts/gates/EXCEPTIONS.md 登记例外"; exit 0   # ③ 豁免逃生口
fi
# ④ 采集 → 判定
# ⑤ PASS 分支 exit 0
# ⑥ 违规分支：先说清「哪条规则、原文是什么、当前 vs 基线」，再列 文件:行 样例 → exit 1
```

**② 为什么必须存 `RULE` 变量**：违规输出的价值在于让人 3 秒内知道「我违反了哪条」。
只贴 grep 结果 = 让人自己去翻文档 = 门禁白做。

## 三、两种门禁形态

### 判定型（存量干净时）

`current == 0 → PASS`。适用于「新增即违规」且存量已清零的场景。

### ratchet 型（存量有债时）

```
current <= BASELINE → PASS
current >  BASELINE → 违规，列命中样例
```

- `BASELINE` 是**实测值**，不是估计值
- 只减不增：清存量时同步下调 BASELINE，让它变成真正的棘轮
- 报告里永远带 `current=X baseline=Y`，让人知道是在变好还是变坏

## 四、EXCEPTIONS 协议

「违规必须修复**或登记**」的登记处，一行格式：

```
gate-<编号> | YYYY-MM-DD | 原因
```

- 登记后该 gate 立刻 `SKIP` + `exit 0`
- 登记表必须存在（空文件也要建），否则 gate 里的 `[ -f ... ]` 永远假，豁免机制形同虚设
- **登记表本身要有单点**：只允许这一处，不许在规则文件里另写「本条豁免」

## 五、自测协议（不测过的门禁等于没写）

每个脚本必须证明**能抓到**违规，不只是「跑起来没报错」：

1. 构造一个**最小违规样例**（改一个文件、加一行违规）
2. 跑脚本 → 断言 **exit != 0** 且输出含 `文件:行` + 规则原文
3. 撤销样例 → 跑脚本 → 断言 exit == 0
4. **样例用完即删**（不留临时文件）

**被安全护栏拦时的绕法**：如果构造样例的命令本身会触发护栏（例如涉及敏感文件名），
不要绕过护栏，改用 **mock 桩**：在临时目录放一个假的 `git`（或对应 CLI），让它输出你要的清单，
把 PATH 指过去。这样既不碰真实敏感文件，又顺带验证了脚本的解析逻辑。

## 六、已踩过的 6 个坑

### 坑 1：基线手测值 ≠ 真值（引号二次展开）

命令行手测含 `$&` / `!$` 的正则时，外层 shell 会把它们当成自己的特殊变量展开，
正则被篡改 → 数出来的结果偏大（实测 647 vs 真值 618）。

**修法**：基线一律在**脚本文件内**测（脚本里少一层引号），再用独立方法交叉验证
（`wc -l` / `awk` / `grep -c` 三计数一致才算数）。

### 坑 2：`grep -c` 遇空结果返回非 0 退出码

`count=$(grep -c . file)` 在零命中时会让 `set -e` 的脚本直接退出，
看起来像「脚本崩了」而不是「通过」。

**修法**：`| grep -c . || true`，或 `$(... || echo 0)`。

### 坑 3：安全护栏拦的是**命令**，不是意图

构造违规样例时命令里出现敏感文件名（如 `*.env`）会被直接拦。
**这是护栏设计正确**，不要试图绕过；改用 五 的 mock 桩（假 git 桩）。

### 坑 4：Edit 吞换行导致变量未赋值

替换脚本某一段时，把两行合成了一行（`dir="$(cd ...)" grep ...`），
变量赋值没生效 → 后面全部用空串 → 计数恒为 0 → **看起来通过了，其实没跑**。

**修法**：改完立刻跑一遍真实扫描，看计数是否合理。计数为 0 而预期非 0 = 立刻现形。

### 坑 5：模板占位符用 `<>` → shell 重定向

写脚本模板时习惯性写 `grep -rn '<字面量>' <扫描范围>`，
`<` 在 shell 里是重定向符 → 模板**自己就语法错误**（`syntax error near unexpected token '2'`）。

**修法**：占位符一律用 `__大写下划线__`，永远 shell 安全。
**验证**：模板文件也要 `bash -n` 过，不能只看一眼。

### 坑 6：`||` 与 `&&` 左结合

```bash
ROOT="$(git rev-parse --show-toplevel || cd "$(dirname "$0")/../.." && pwd)"   # 错
```

shell 里 `a || b && c` 等价于 `(a || b) && c`：git 成功时 `pwd` **仍然执行**，
两段路径被拼成两行 → 后续 `cd` 必失败（报错里路径中间夹着换行，一眼能看出来）。

**修法**：用 `if X="$(...)" && [ -n "$X" ]; then :; else X=...; fi` 显式分支。

## 七、README 索引（每个仓一份）

`scripts/gates/README.md` 至少含这列：

```
| 编号 | 规则 | 原位置 | 检查口径 | 基线 |
```

- **原位置必写**：删正文留指针后，编号是唯一的寻址方式
- **口径必写**：换个人接手时，只有口径列能告诉他这个 gate 到底在数什么
- 附一条**口径注记**，记录本仓踩过的计数陷阱（如引号展开），避免后人重新踩
