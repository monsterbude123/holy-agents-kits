# study/ 学习包规范

学习包 = 把视频内容加工成「能学走」的材料。模块按学习者画像裁剪，不整套硬产。

## 模块清单与裁剪决策表

| 模块 | 何时产 | 解决什么 |
|---|---|---|
| `README.md` 导航 | 必产 | 每个文件解决什么+优先级+2–3 条使用路径（冲刺 / 系统 / 速查） |
| 逐主题原理深挖（N 篇） | 必产 | 按视频章节一篇：机制为什么这样设计、边界在哪、何时失效 |
| 术语速查 | 必产 | 每个术语一句本质+什么时候用得上 |
| 概念迁移对照表 | 学习者有旧领域经验 | 旧经验↔新概念双向映射，含「不能想当然的差异」 |
| 题库 | 面试/考核导向 | 每题：原理层答案+结合学习者经历的答法+追问链 |
| 动手验收标准 | 实操导向 | 每阶段「做到什么程度算过」的可验证判据 |
| 前置知识清单 | 入门导向 | 缺哪些前置、补到什么程度就够用（不过度铺开） |
| 方法论/元技能篇 | 学习者诉求是「散、不成体系」 | 教他自己归位知识的结构化工具（分层、四层深挖法等） |

裁剪依据 = Step 0 画像：目标定选配方向（面试→题库、上手→验收标准、入门→前置清单），既有经验定要不要迁移表。拿不准就问一句，不要替学习者猜场景。

## 各文件骨架

**README.md 导航**：文件表（文件 | 解决什么问题 | 优先级）+ 使用路径（按学习者可用时间给 2–3 条：如 1 周冲刺怎么读、系统学怎么读、考前 2 小时速查读哪些）+ 阅读约定（符号含义）。

**逐主题原理深挖**（一篇一个主题，文件名 `NN-主题-原理.md`）：
1. 这东西解决的核心矛盾（不是「它是干什么的」，是「它调和了什么冲突」）
2. 机制怎么跑起来的，关键一步在哪
3. 什么条件下失效/退化（★ 分水岭，多数人答不出这层）
4. 不用它怎么做，代价差在哪
5. 与学习者既有经验的连接点（有迁移表时指向它）

**概念迁移对照表**：三列表 = 旧领域概念 | 新领域概念 | 不能想当然的差异；每行差异必须具体到「照旧直觉会怎么错」。

**题库**：按主题分组；每题三段——原理层答案 / 结合 `[填空]` 经历的答法 / 面试官可能的追问。

**动手验收标准**：每阶段列可机器或他人判定的判据（「跑通 X 并输出 Y」能判，「理解 X」不能判）；配复测方式。

**术语速查**：表格 = 术语 | 一句话本质 | 什么时候用；按出场章节排序。

**方法论篇**：只在学习者自述「知识散/知道但说不出」时产；给结构化工具（如四层深挖：现象→机制→原理→迁移），并配本周动手任务。

## 三条纪律

1. **数字可溯源**：学习包里每个数字标视频时间戳，或明确标「视频外补充」；不许无出处的数。
2. **`[填空]` 不代填**：需要学习者本人真实经历/数字的位置写 `[填空：<要填什么>]`，空着比编造强。
3. **原理优先**：每篇深挖必须回答「为什么这样设计+什么时候失效」；只复述 API 用法的篇视为未完成，返工。
4. **不虚构**：视频没讲的不混进正文；确需补充的知识明确标「视频外补充」并说明补它的原因。
