# 披露与审美

「一眼全图」和「披露式明细」是同一个动作的两端：图负责让人知道**有什么、在哪、叫什么**；明细负责让人**读下去**。审美不是装饰——配色、字号梯度、对比度、密度策略直接决定「一眼全图」能不能成立。

## 1. 三级披露

| 级 | 载体 | 内容 | 触发 |
|---|---|---|---|
| 概览 | 画布节点 + 顶栏计数 | 分组色、标题、规模数字 | 打开页面 |
| 摘要 | tooltip | 一句话（≤140 字）+ 文件名 | 悬浮 |
| 全文 | 明细面板 | 标题 / 一句话 / 正文（渲染后的 md） | 点叶节点 |

明细面板的段序固定：**标签 chips（分组 / 文件名 / 节点类型） → 标题 → 一句话 → 正文**。先给定位，再给内容。

- 正文渲染要保留 md 结构：标题、列表、引用块、行内代码、代码块。
- 长文必须可滚动，面板本身不撑破视口。
- `Esc` 关闭，点空白关闭；关掉后不残留遮罩。

## 2. 色板（深色 OLED）

```
--bg    #0F172A    页面底
--panel #1B2336    面板 / tooltip
--muted #272F42    次级底
--line  #475569    分隔线
--fg    #F8FAFC    主文字
--dim   #94A3B8    次要文字
--accent #22C55E   强调 / 命中态边框
--gold  #F59E0B    搜索命中
--bad   #EF4444    缺内容（无摘要）
--link  #5B9DFF    关联链接
```

规则：

- 正文对底色对比度 ≥ 4.5:1；次要文字 ≥ 3:1。深色底上纯白刺眼，用 `#F8FAFC` 而非 `#FFFFFF`。
- **分组色是身份**，不是装饰：同一分组在全图、明细 chips、图例里必须是同一个颜色。
- 分组色要互相可辨（10 色板已按色相拉开），并且在深色底上都有足够亮度。
- 命中金色只给「被搜到」的东西，不要大面积用。
- 缺失信息用 `--bad` 明说「（无摘要）」，不要留空——留空会被当成「加载中」。

## 3. 字号梯度

| 对象 | 字号 | 字重 |
|---|---|---|
| 根节点 | 15 | 700 |
| 分组 | 14 | 700 |
| 文件 | 12.5 | 600 |
| 叶/段 | 11.5 | 400（命中 700） |
| tooltip | 12 | 400 |

层级靠**字号 + 字重 + 颜色**三重区分，不能只靠颜色（色盲、投影、截图都吃亏）。

## 4. 密度策略

- 可见叶节点 ≤ 40：全标签。
- 超过 40：叶/段只画点不画标签，文件标签保留并加半透明底衬。
- 搜索态：**强制显示标签**（否则「搜到了却看不见」）。
- 点开一个分支只多展开那一支，其余保持收起——不要因为点开一个就把整棵树摊平。
- 图例放**右上竖排**，不要放左下浮层：左下是树的叶子密集区。

## 5. 排版细节

- 标题不换行超过两行；过长时截断并在 tooltip/明细里给全名。
- tooltip 宽度封顶（`max-width:340px`），`white-space:normal`，多行可读。
- 正文里的表格、代码块要横向可滚，不要撑破面板。
- 明细里的**关联 chips**：显示目标标题，点了能跳到那个节点（跳过去后目标要展开并高亮）。
- 顶栏放规模数字（文件 / 组 / 叶节点 / 有关联 / 搜索命中数）——读者第一眼要知道这图有多大。

## 6. 自检（审美向）

改完配色/密度后，逐条对：

1. 缩小窗口看分组色还认得出来吗？
2. 截图给一个「不熟这个领域」的人看，他能说出「有哪些大块」吗？
3. 悬浮时 tooltip 里的第一句话，单独看能懂吗？
4. 点开明细后，正文里有没有跟图上一模一样的重复段落（有 = ownBody 规则没生效，见 parsing.md §2）？
5. 全展开一次，标签有没有互相压字？压了就调 `LABEL_LIMIT`，别调字号到 9px 以下。
