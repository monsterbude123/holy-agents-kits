# 盘结构与解析规则

## 1. 先盘，再写配置

盘结构这一步的产出是三件事，写进 `surface.config.json`（或记在心里）：

| 要盘的东西 | 怎么盘 | 写进哪 |
|---|---|---|
| 有几个文件、什么语料 | `find . -name '*.md' \| wc -l` | 决定是否拆多张 surface |
| 标题有几级、什么算叶 | 抽查 3 份：`grep -n '^#' file.md` | `summarySections` / `--leaf-pattern` |
| 怎么分组 | 看目录名；目录拍平就看文件名里的编号/日期 | `groups[].match`（正则，匹配**不含扩展名**的文件名） |
| 一句话从哪取 | 找语料里「答案/摘要/结论」这类段名 | `summarySections` |
| 有没有既定配色 | 语料若已有领域色板（别的界面在用），照抄 | `groups[].color` / `palette` |

**分组不靠猜**：语料若已有人工校准过的领域划分，照抄不重造。自动聚类的分组看起来聪明但不可信——读者要的是「跟人想的一样」的分区。

```json
{
  "title": "示例语料 · 25 天学习图谱",
  "groups": [
    { "id": "gateway", "name": "AI 网关", "color": "#5b9dff", "match": "day-0[234]" },
    { "id": "method",  "name": "Agent 方法论", "color": "#3ecf8e", "match": "day-0[56]" }
  ],
  "summarySections": ["答案", "摘要", "一句话", "结论"],
  "palette": ["#5b9dff", "#3ecf8e", "#f0b429"]
}
```

未命中任何 `match` 的文件落进「其它」组（灰色）。`groups.match` 是对**文件名**（不含扩展名）的正则；完全不配 `groups` 时按第一层目录归组，根目录文件归「其它」。

## 2. 解析链（build_surface.mjs 的实际顺序）

```
walkMd(dir)            递归收 *.md，路径用 / 分隔
  ↓ findHeadings(lines)  取标题行；代码围栏里的 # 不算标题
  ↓ markRanges(heads)    每个标题的正文范围 = 到下一个同级或更高级标题前
  ↓ linkParents(heads)   用同级栈建父子（跳级会自动挂到最近的祖先）
  ↓ ownBody(lines, h)    只保留本节点自己的行（排除子标题覆盖的行）
  ↓ splitSections(body)  按 **标签** / --- 把正文切成段
  ↓ pickSummary(...)     每段→摘要候选
```

- **标题层级即结构**：md 的 H1→H4 天然是树。「卡片」写法（`### 卡 1 · 标题`）本来就是 H3，不需要另写解析器。只有当「卡片」标记出现在正文而非标题时，才用 `--leaf-pattern` 正则。
- **跳级标题**（H2 下面直接 H4）自动挂到最近的祖先，不报错——真实语料里很常见。
- **ownBody 的意义**：H3 的正文不能包含 H4 的正文，否则子节点的内容会在父节点摘要里重复出现，展开后会看到同一段文字两次。

## 3. 摘要规则（叶节点必须有摘要）

摘要缺失 = 界面退化成目录。取值顺序（`pickSummary`）：

1. **designated 段**：`summarySections` 里命中的段（默认 `答案 / essence / 摘要 / 一句话 / 结论 / 核心结论`）。
2. designated 段**标签独占一行、内容在下一段**时 → 取其后第一个有内容的段。
3. 首个命名段（`splitSections` 切出来的带标签段）。
4. 首个实质行（跳过纯标记行、纯标签行、表格行）。
5. 围栏里的纯文本（跳过图形化围栏）。
6. 表格首行数据（跳过表头）。

最后在**句边界**截断（`firstSentence`，默认 140 字）。别在词中间砍。

**必须跳过的内容**（否则摘要有毒）：

| 内容 | 判定 | 为什么 |
|---|---|---|
| 图形化代码块 | `DIAGRAM_LANG = /^(mermaid\|graph\|flowchart\|sequencediagram\|plantuml\|dot)$/i` | 图不是摘要，是图 |
| ASCII 框线图 | `DIAGRAM_CHAR = /[\u2500-\u257F]\|▶\|►\|▼\|▲\|◄\|◀\|➡\|➤/` | 框线字符拼出来的图，摘要是乱码 |
| 分隔线 `---` | stripMd 后为空串 | 不是内容 |
| 表格行 | `^\s*\|` | 表格有专门结构，摘要是碎片 |
| 复选框 | `^\s*\[[ xX✓✔]\]\s*` | 任务符号不是内容 |

**「纯标签行」判定要严**：整段加粗的正文会被误判成小节标签。用 `LABEL_RE = /^[^*\n]{1,16}$/` + 不含 `。！？，、；` 来卡；只看长度会翻车。

## 4. 段切分（splitSections）

正文切成段有三种触发：

1. `**标签**` 独占一行 → 该行是段标签，内容是后面的行；
2. `**标签**：内容` 同行 → 标签 + 内联内容；
3. `---` 分隔线 → 强制断段。

段标签判定用 `labelOk()`（≤16 字、不含句末标点）。**整段加粗的正文必须被排除**，否则「`**一、结论**`」这种写法会把整篇当标签。

## 5. 常见坑

- **围栏里的 `#` 不是标题**：先做围栏状态机再取标题，否则示例代码块会凭空长出一棵子树。
- **文件名里的日期编号不是结构**：`day-02-学习任务.md` 是文件名，不是节点；文件是叶子容器还是分组容器由 `groups.match` 决定。
- **文件内多张卡片**：每张卡是独立叶节点（`### 卡 N · 标题` → 一个 H3）。一张卡就是一个叶，天然对应「一眼全图 → 点开看明细」。
- **表格型小节**（「三句口诀」「自测六问」）没有标题层级，只能作为所属卡片的内容，不会独立成节点——这是对的，它本来就不是可导航单元。
- **空文件 / 只有标题**：会产生没有摘要的节点 → 自检会报 warning，先补内容或把它并进父节点。

## 6. 自检（脚本已内置）

跑完构建看 stderr：

```
[ok] 25 文件 / 10 组 / 573 叶节点（641 节点，437 个有关联）
[warn] N 个叶节点没有摘要：…
[warn] 孤儿节点 N 个
```

**这两个 warning 必须是 0**。有 warning 就回去修解析规则，不要改数据源迁就脚本。
