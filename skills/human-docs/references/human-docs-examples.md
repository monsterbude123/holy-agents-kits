# 甲乙糅合正反例(「甲乙裁决」的配套判例)

甲 = 面向人类读者的表达层;乙 = 面向 agent 的记忆层。判据见 SKILL.md「甲乙裁决」;本文件只放判例,不加新规则。

## 例 1:甲层文档塞代码引用(反例 → 拆)

反例(一篇给人验收看的文档里的小节):

> ### 附录:关键代码引用
> 入库校验逻辑见 `src/validator/ingest.ts:88-120`,禁词表加载见 `src/rules/loader.py:41`。

病:读者是验收的人,却拿到只有开发者能用的坐标;文件一挪,坐标全成误导。
正解:甲件正文写可观察行为(「提交前逐条扫描禁词表,命中即拒绝」);file:line 证据写进乙层手记或自检工件的抽查记录。

## 例 2:同一行为两处写全(反例 → 一处权威 + 一行指针)

反例:README 写全了配置方法,docs/config.md 又写一遍——三个月后漂移成两套互相矛盾的说法。
正解:docs/config.md 权威;README 一行指针指向它(指针指向读者相同的人读文档,不指向源码)。

## 例 3:过程手记当人读文档发(反例 → 读者分离)

反例:把会话过程手记(「试了三种方案,B 走通了」)直接粘进给人看的 README。
病:过程叙事对没参与开发的人是噪音,日期漂移成误导。
正解:README 只留结论与用法;手记留乙层,或按焚毁协议丢弃。

## 例 4:测量记录的乙层正形

档位表 + 机器可读证据文件 + 复测入口,是乙层实测记录的骨架:数字入库到 JSON,正文只留口径与边界。日期在乙层允许(记录何时测的),但「此前记的是……」式的自我纠偏过程不进——结论只有当前版,没有编年史。

## 例 5:图深度(甲层判例)

反例:总览架构图把每个类都画进去,50+ 节点一屏塞不下。
正解:总图 ≤3 层(入口 / 主干 / 末端类别);排障所需的叶子级细节拆子图,与总图同文档就近放置、挂对应节点。
