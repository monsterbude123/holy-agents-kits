# codebase-slimming · 巨石代码库消肿与安全拔除方法论

输入：业务功能寥寥但代码量达数十万至百万行、多次治理效果不显、死代码与多代活地层纠缠的水肿系统。
产出：全景代码分布账本、数万行真实物理净减（`git diff --stat`）、新端完全自立解耦、只紧不松的增量防线。

**边界**：只管巨石治理主线（摸底 → 分立 → 拔除 → 棘轮）；不做单模块小型重构、不做性能优化、不做通用代码审查；语义判定工具委托 vscode-backend 技能（见 MUST 1）。

## 主轴：四步执行流程（摸底先行）

```
Step 1 全景摸底 ──> Step 2 三权分立 ──> Step 3 剪断寄生 ──> Step 4 整包拔除与棘轮
```

| 步骤 | 核心动作 | 退出判据（不满足不进下一步） | 岔路与避坑 |
|---|---|---|---|
| **Step 1 全景摸底** | 跑 `cloc` 产出互斥四桶；统计 src 分域排行；二阶下钻模糊大桶；用 AST/vscode-backend 解析跨域边与死代码闭包 | 《全景代码分布账本》五表齐备，死代码比例（通常 ≤3%）锁定 | 死代码极少时立即分叉到 Step 2 查老地层，严禁在死代码上死磕；大桶 >10万行必下钻 |
| **Step 2 三权分立** | 将资产划分为：在途资产 / 平台核心 / 待平替老地层 | 明确唯一拔除靶心，严禁误伤在途与核心 | 目录名带歧义时以导入图为准，严禁望文生义（实测案例见 case-study §1） |
| **Step 3 剪断寄生** | 抓取「新系统 → 老模块」跨域边（通常 20~30 条）；新端内建自包含组件 | 新系统对老地层的生产调用边完全归零 | 新系统在抽屉/弹窗中偷调老组件时，必须先在新端重构，不可直接删老模块 |
| **Step 4 整包拔除** | 物理删除老模块 UI、对应老 API 路由与专属测试；配置 jscpd/门禁 | `git diff --stat` 净减数万行；门禁全绿 | 严禁生成数千行 suppressions/allowlist 伪造假绿；严格规则只拦 staged 增量；API 路由拔除前查仓外消费方（网关日志/移动端），拔后留 404 观察期 |

## §1 核心铁律（不可协商）

```yaml
MUST 0: 动刀前必须先出具《全景代码分布报告》（绝不盲目开工）
  - 严禁在未摸清全景分布前动手！治理前置必须出齐五张账本：
    ① 全仓互斥四桶（src / tests / scripts / docs&assets）
    ② src 分域物理行排行（前 5~10 大域真实占比）
    ③ 模糊大桶二阶下钻（如平台层/其他 >10万行时，必须拆解为真底座/独立运行时/误分类域/胶水）
    ④ 跨域真实依赖拓扑（以 import 边数验证交集，证实或证伪业务关系）
    ⑤ 真实死代码可达闭包（明确死代码实际占比，通常 ≤ 3%）

MUST 1: 语义判定走真实 AST/IDE 语义后端，计数工具只管行数体量
  - 行数统计以 cloc 为准，区分代码/注释/空行/二进制；
  - 依赖可达性 / 引用查找 / 诊断 / 影响面一律走 vscode-backend 技能（VS Code 语义后端，引用/诊断/影响面/改名均带实测档位表）。
    获取：`npx skills add monsterbude123/holy-agents-kits --skill vscode-backend`（加 `-g` 装全局）
    或 GitHub：https://github.com/monsterbude123/holy-agents-kits/tree/main/skills/vscode-backend
  - 严禁手搓脆弱正则匹配 import，严禁把未使用的 export 误读成未引用文件。

MUST 2: 动手前必做三权分立，确定唯一拔除靶心
  - 在途资产（开发了一半的模块）：绝对保护，保持现状不碰；
  - 平台核心（账号/网关/队列/错误码）：正名保留，不予折腾，只守增量；
  - 待平替老地层（历史向导/旧版实现）：唯一手术目标，整包拔除。

MUST 3: 严格先拆寄生引线，再拔老地层
  - 新系统往往在抽屉或弹窗中暗中引用老模块（寄生现象）；
  - 必须先在新端自立自足（重构自包含组件），使老模块生产调用边归零后再物理删除。

NEVER 1: 严禁自造数千行豁免新债（伪造假绿）
  - 严禁为了跑通门禁生成几千行的 suppressions/allowlist 文件将错误合法化；
  - 严格遵守「增量硬拦截」：严格规则只拦 staged 暂存区，存量不膨胀词典。

NEVER 2: 严禁将业务地层降级为轻量删死代码
  - 真正能砍下几万行体量的，永远是已被新功能平替的「整包老业务地层」；
  - 严禁 agent 发现有引用就单方面退缩为“只删几十个死文件交差”。

ROLLBACK: 出现未预期编译报错时的回退路径
  - 整包拔除采用原子 commit；如发现深层遗漏依赖，立即 git revert 该 commit，回到 Step 3 补齐新端自立。
```
