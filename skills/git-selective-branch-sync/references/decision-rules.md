# 解冲突的判断依据

三方合并产生冲突块后，逐块按这里的规则定。**不要整文件取一边。**

---

## 1 总原则

> **目标分支为骨架，源分支的语义移植进去。**

目标分支通常已含上游的新版实现。整文件覆盖等于把上游的改进也退掉；
整文件取源分支等于丢掉目标分支上用户明确要保留的东西。

真正需要判断的只有两类：

- **两边改同一处逻辑** —— 看语义是否兼容，兼容就并集，不兼容就按「谁的行为是契约」
  定，并记下取舍。
- **源分支的钩子挂在目标分支已重写的流程上** —— 见 §3。

---

## 2 逐情形判断表

| 情形 | 取法 | 理由 |
|---|---|---|
| 两边改同一文件的不同位置 | 自动合上（`merge-file` 已处理） | 无需判断 |
| 两边在同一位置加**不同**字段 | 并集，两个字段都留 | 典型：上游加字段 A、源分支加字段 B |
| 两边改同一行**语义兼容** | 并集 | 典型：上游换日志文案、源分支换错误码 |
| 两边改同一行**语义冲突** | 按契约定：谁的写法是**对外契约**就留谁 | 契约优先于实现细节 |
| 目标分支删了文件、源分支改了它 | 保留删除，但要确认源分支的改动是否被别处依赖 | 上游删除通常有理由 |
| 两边各自新增同名文件 | 取源分支，但**必须记录** | 归属由人决定，不自动覆盖 |
| 源分支独有的文件 | 直接取，先过不同步台账过滤 | 零冲突 |
| 源分支独有的目录（整包） | 整包取，**含其中的可执行资产** | 见 pitfalls P6 |

---

## 3 语义移植的标准做法

目标分支重写过核心流程时，源分支的钩子会失联。移植三件事：

1. **函数体** —— 从源分支取，但适配目标分支的类型/签名变化。
2. **调用点** —— 目标分支的新流程里位置可能完全不同。先读懂新流程再决定插在哪。
   典型插入位：拿到新上下文之后、发起副作用之前。
3. **生命周期** —— 源分支的钩子常带资源释放、请求作用域绑定、计数器自增。
   漏掉生命周期 = 功能「看起来在但没生效」或「资源泄漏」。

**自检**：移植完成后问三个问题 ——
函数被调用了吗？在正确的位置吗？它的资源释放 / 计数器 / 作用域绑定还在吗？

## 4 结构化文件（locale / schema / 配置）

**用解析器合并，不用文本行插入**（pitfalls P3）。

| 步骤 | 做法 |
|---|---|
| 定位对象边界 | 先找到目标对象的开括号，只在边界内做键集合计算 |
| 键集合 | 取并集 |
| 值冲突 | 同 key 不同值时，看**代码实际用哪一版**；代码用新措辞就改 key 名对齐代码（pitfalls P8） |
| 排除项 | 源分支起点已有的条目要排除，否则复活上游删掉的东西（pitfalls P5） |
| 写后校验 | 校验顶层键数、目标对象条目数、JSON 合法性、**各语言条目数一致** |

**多语言 locale 类文件，各语言条目数必须一致** —— 不一致说明某一步只处理了部分语言。

## 5 凭据与内网地址

| 类型 | 迁入时的处理 |
|---|---|
| 硬编码 token / API key | 改环境变量 + 空串默认值；脚本启动时校验非空 |
| 硬编码密码 | 改环境变量 + 空串默认值 |
| 内网地址 / 端口 | 改环境变量 + 占位符默认值（`example.internal`） |
| 唯一配置源（含真实凭据的 `config.json`） | **保持不入库**，用本地排除（`.git/info/exclude`） |
| 文档里的凭据声明表 | 改写为「脚本内不含真实凭据 + 逐项列环境变量 + 使用示例」 |

迁入后必须扫描一遍：`sk-` 前缀、已知内网网段、`password:` 字面量、已知 token 前缀。

---

## 6 不同步清单的处理

台账上的每一项，落地时要有明确落点，不能只「不迁」了事：

| 不同步类型 | 落点 |
|---|---|
| 凭据类文件 | 不迁 + 加本地排除 + 在文档里说明它在哪 |
| 本地工具链 | 不迁 + 加本地排除 |
| 已被上游取代的实现 | 不迁 + 在文档里指向取代者 |
| 内容敏感但要保留的文档 | **迁，但脱敏**（地址/口令换占位符） |
| 只想同步部分子目录 | 迁该子目录，其余留排除清单 |

**收尾时逐条对账**：「用户说不迁的」是意图，「实际没迁的」是结果，
两个集合逐条比，才算完成。
