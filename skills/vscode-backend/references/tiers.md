# 档位口径 —— L0-L5 与每档判据

> 本技能**自带**这一份档位定义（独立分发要求：另一技能 idea-backend 可能没装，引用它的仓内文件会缺件）。
> 口径与另一技能 idea-backend 的档位表**同源**（同一套 L0-L5 分级思想），但**各存一份**、互不引用 —— 另一技能的档位定义在它的 capability-matrix 文档 §1/§2。
>
> ⚠️ **两处口径分歧（跨后端对照时要注意）**：本侧 **L0 = 文件结构化符号清单**、**L1 = token/高亮/片段匹配**；另一技能的 L0/L1 是「按名字找到源文件」/「带上下文的文本检索」（那是它的工具面决定的）。⇒ **L2-L5 两边语义可对齐，L0/L1 不可比** —— 做两臂对照时这两档要么对齐口径重测，要么明确排除。

## 1. 六档定义

| 档 | 名字 | 判据（满足这一档要能做什么） |
|---|---|---|
| **L0** | 文件级 | 能拿到一个文件的**结构化清单**（符号/元素列表），不要求跨文件语义 |
| **L1** | 文本级 | 能拿到文本级信息（token/高亮/片段匹配），不要求符号身份 |
| **L2** | 符号级 | 能按**符号**做语义检索：定义 / 引用 / 调用者 / 工作区符号（身份确定，不是文本匹配） |
| **L3** | 检查级（单文件） | 能列出**一个文件里**的全部诊断/问题，并给出规则来源 |
| **L4** | 检查级（全局/范围） | 能对**一个范围**（如整个项目）批量出诊断/问题清单 |
| **L5** | 重构级 | 能做**安全重构**：改名/删除前给出**影响面**（受影响的文件与位置），并能撤回 |

> 判据的关键分界：**L2 要的是「符号身份」**（同名同物），**L3/L4 的分界是「范围」**（单文件 vs 一批文件），**L5 要的是「影响面 + 可撤回」**（只给建议不算）。

## 2. 机器可读缺口清单

（供门禁逐格核对：`measured_tiers` = 有实测凭证的档；`gaps` = **行键 → 缺口来源**，来源文本要能在表里逐字找到）

```json
{
  "measured_tiers": ["L0", "L1", "L2", "L3", "L5"],
  "gaps": {
    "L3@bifrost-mcp": "实现层：实测 get_code_actions 报 Illegal argument（内部 vscode.executeCodeActionProvider 收到 undefined 的 rangeOrSelection），扩展 0.0.14",
    "L4@lsp": "协议层：LSP 的 textDocument/codeAction 请求没有 scope 参数，协议里没有「一次批检视一个范围」这个能力；VS Code 侧 19 个工具里也没有对应工具",
    "L5@bifrost-mcp": "实现层：实测 get_rename_locations 报 Unexpected type，扩展 0.0.14"
  }
}
```

**这张表的读法**：
- `measured_tiers` 是**本机实测**过的档（凭证在 `references/measurements/`）；
- `gaps` 的值是**可逐字核对的来源**（实测错误原文 / 协议层事实），不是印象；
- 某个档在**不同路线**上状态不同时，按路线各写一行（行键 = `档@路线`），gap 的来源写进那一行的判据列。

## 3. 探测判据（怎么算测到了）

- **符号级工具数 ≥ 4**（判定锚 = 6 个已知符号级工具：`find_usages` / `go_to_definition` / `get_workspace_symbols` / `get_document_symbols` / `get_rename_locations` / `get_type_definition`）；
- **诊断工具必须正是 `get_code_actions`**（VS Code 扩展侧没有独立的 problems 工具）；
- 位置约定：**line 零基准**（扩展的 schema 文本写 One-based，与实现不符 —— 以实现为准）；uri 必须是 `file:///<小写盘符>/<正斜杠路径>`。

> 这三条判据的出处与实测记录见 `references/setup.md` 的机器可读事实块。
