# 云盘治理决策手册

什么时候读：定分类法时、用户问「该删什么」时、写索引时。

---

## 1. 先分清两种「乱」

| 症状 | 真实问题 | 对策 |
|---|---|---|
| 目录名看不出装了什么、翻半天找不到 | **分类乱** | 重排：按用途建分类树 |
| 目录名正常，但体量大得离谱、几年没碰 | **囤积乱** | 先决策去留，再谈分类 |

十几 TB 量级 那个网盘两者都有，而且第二类占大头。**先做第二类的决策，再做第一类的搬家** —— 否则就是把垃圾搬得更整齐。

---

## 2. 识别「体量-用途错配」

目录名和体量不符 = 囤积的信号。四个查法：

1. **目录名里的标称体积 vs 实际体积**。`尚硅谷全套JAVA教程—实战项目（71.89GB）` 实测 208 GB —— 标称只覆盖了当年打包时的那部分。
2. **扩展名分布**。`.mp4` 占 90% 体量 = 这是录像不是文档。`.avi` 310 GB / 4851 个 = 2005~2020 年的老课程。
3. **文件年龄**。`server_ctime` 集中在 2014 / 2017 / 2020 / 2023 四年 = 一次性囤的包，不是在用的库。
4. **子目录名与内容不符**。`某电商课程包` 下 70.6 GB 是游戏直播回放（单个 17.7 GB）。

问用户时的说法要具体到体量与证据，不要泛泛问「要不要删」。

---

## 3. 分类法：按用途，不按来源

**错误**：按来源分（`我的资源`、`课程`、`工具整理`）。`我的资源` 是杂物袋 —— Houdini 教程、UE 资产、音效、小说、Java 技术书、债券计算器课件混在一起，因为它们「都是别人给的」。

**正确**：按用途分，每个分类能回答「新东西往哪放」。

```
00_正在做/       手头在推进的（每周一清）
01_AI/           一个领域的所有相关物（模型/工作流/笔记/部署）
02_课程/         学过的课（按学科分二级）
03_素材库/       可复用资产（按素材类型分二级）
04_软件与工具/   安装包
90_待清理/       隔离区
99_索引/         README
```

要点：

- **数字前缀 = 使用频率**，让人一眼知道先翻哪个
- **二级按内容维度**：课程按学科、素材按类型、工具按用途。不要混
- **一个领域的东西别拆散**：模型、工作流、提示词、笔记放一起，否则每次都要跨目录找
- **顶层控制在 6~8 个**：再多就等于没分类

---

## 4. 重复判定：只有 md5 相同才算

目录名相似不算；标称体积相似不算；「看起来一样」不算。

**整棵隔离的前提**：该子树内**每个文件**的 md5 都能在保留侧找到。哪怕只差一个文件，就只能隔离到文件级。

实测教训：两个 1.3 TB 的课程包目录名几乎一致、章节编号体系也一致，看着像同一套资料的两份 —— 深扫后发现**章节集不同**（A 独有 7 章、B 独有 6 章），是两套不同的课程，只能隔离其中 2 个真正重合的子章节。

---

## 5. 隔离而非删除

MCP 工具集里**没有删除**，只有 move/rename/copy。所以：

- 「清理」= move 到 `/90_待清理/<分类>/`，由用户在客户端删（进回收站，可恢复）
- 隔离区要有 README，写清每项**原路径**和**隔离理由**，用户才能放心批量删
- 破坏性操作（删除、覆盖、批量移动/改名）执行前必须让用户确认

**取舍**：宁可多留一份，也不要把不确定的当重复删掉。隔离是可逆的，误判的代价只是占着空间。

---

## 6. 重排的执行顺序

1. **先建骨架**（空目录），避免中途出现半成品结构
2. **先移子项、后移父目录**。父目录在子目录搬走后成了空壳，再整体搬走
3. **父目录不能 move 进自己的子目录** —— `/课程` 往 `/02_课程` 搬会失败
4. **目标名撞车**时换名（`/01_AI/模型库` 已存在 → `/AI模型仓库` 搬成 `/01_AI/模型库/AI模型仓库`）
5. 移完把空壳归拢到 `/90_待清理/空壳/`，根目录才干净

---

## 7. 索引写法

`/99_索引/README.md` 至少包含三块：

1. **顶层表**：目录 → 放什么 → 体量。体量带单位并注明是实测还是标称
2. **新东西往哪放**：一条条路径，让人不用重新判断
3. **待用户决策清单**：体量 + 最后活动年份 + 为什么可疑

再把「网络只灌数据、分析走本地库」的维护命令贴进去 —— 索引要能自己更新，否则三个月后又是一份过期文档。

---

## 8. 报告给用户时怎么说

- 先给**结论**（网盘不乱，是囤了 X TB 几年没碰的课），再给证据
- 体量数字要标明是实测还是下界（扫描撞上限时是下界）
- 破坏性建议列成表，让用户勾选，不要替用户决定
- 老实说哪些没查、哪些数字偏低、哪些风险还在
