# 反例：脚本与运行时（工具层的坑）

> 这一组全是**脚本/工具层**的坑：参数解析、并发、幂等、MCP 返回格式、扫描剪枝。
> 网盘 API 与用法本身的坑见 [counter-examples.md](counter-examples.md)。

---

## D. 脚本与运行时

### ❌ 用 `AbortSignal.timeout()` 然后 `await res.text()`

**现象**：Node 报 `Warning: Detected unsettled top-level await` —— `AbortSignal.timeout()`
的定时器是 **unref** 的，不保活，进程在 fetch 还没返回时就退出了；
加上 `res.text()` 会等**永不结束的流**，看起来像「请求卡住」。

**✅**：`AbortController` + `setTimeout`（ref 定时器）自己控超时，长响应用 `body.getReader()` 增量读。

### ❌ 用 `Number('50MB')` 当体积阈值

**现象**：`dup --min-size=50MB` 跑得**没有任何报错**，stdout 是 `{"ok":true,"data":{"groups":0,…}}`，
`合计可回收: 0B` —— 看起来像「网盘里没有重复文件」。实际同一份库里 **541 组、261.6GB** 可回收。
**原因**：`Number('50MB')` 是 **NaN**，而 `size >= NaN` 恒为 false，筛选条件永远不成立。
姊妹坑：同一脚本里 `big --min=5GB` 查表漏了 `'GB'` 键，回落成倍率 1，
阈值从 5GB 变成 **5 字节**，结果反过来是「全都要」。
两个都不报错、退出码都是 0 —— 这类比报错更坏的**静默假结论**。
**✅**：体积解析统一走 `scripts/args.mjs` 的 `parseSize()`（认 `B/K/KB/M/MB/G/GB/T/TB`，
大小写不敏感），**解析不出来就抛错**；普通数字走 `num()`，同样对 NaN 抛错。
配套铁律：同一个参数解析逻辑**只留一份**，别在三个脚本里各抄一遍——抄三份就会抄出三种严格度。

### ❌ 块内 `const` 遮蔽外层同名变量

**现象**：写「上传后核对远端大小」，代码是
`const remote = await listDir(token, remote.slice(0, …))` —— 块内 `const` 遮蔽了
函数作用域的同名变量，右侧引用触发 **TDZ**，每次都抛
`ReferenceError: Cannot access 'remote' before initialization`，
又被外层 `catch` 吞成「核对跳过」。
**即：这个校验一次都没跑过**，而日志看着一切正常。

**✅**：块内别用外层同名的变量（`remote` → `items`）；更重要的是 ——
**别用 catch 把「代码自己有 bug」和「外部条件不满足」混在一起**：
核对失败要单独 rethrow，其余才降级成「跳过」。
自查：`grep -n "const X = .*X" 脚本` 能扫出一类遮蔽。

### ❌ 续传时不校验本地文件有没有变

**现象**：状态文件只记 `uploadid` 和已传片。上传到一半时文件被改
（重新生成 / 被别的进程替换），重跑时复用旧 `uploadid` → 服务端留着**旧内容**的头几片、
我们再补**新内容**的后几片 → 网盘上是**拼接出来的损坏文件**，
而台账记的 sha256 是新文件的，对不上也查不出来。

**✅**：状态文件里存**文件 sha256 + 切片大小**，续传前比对；对不上就丢弃旧状态、从头来（并明确告诉用户）。
这类「用旧状态续新内容」的组合，静默损坏比不续传更糟。

### ❌ 日志实时写 + catch 里再重放一遍

**现象**：`say()` 实时写 stderr 又把内容存进 `out`，catch 里再 `out.join('
')` 打一次 →
出错时**每行日志出现两遍**。agent 解析日志会以为「传了两次」。

**✅**：二选一 —— 要么 `say` 只收集、末尾统一打一次（像 `baidu-netdisk-db.mjs`）；
要么 `say` 实时写、catch **不重放**。传输类脚本要实时日志，选后者。

### ❌ 校验白名单只收目录，文件级移动全被拒

**现象**：`plan --spec=…` 报「335 项未命中缓存」，合计移动 0B —— 但这 335 个路径
**就是从同一个库里查出来的**（重复副本清理要搬的是文件）。
**原因**：校验用的白名单是 `SELECT path FROM nodes WHERE is_dir=1` —— **只有目录**。
文件级移动（重复副本、旧版本这类「搬单个文件」的场景）**一项都过不了**，
计划直接空掉。目录级移动（重排）不受影响，所以之前没暴露。

**✅**：白名单收全部路径；体积取值分两路 —— 目录用汇总、文件用自身 size。
**教训**：校验器要先想清楚「本流程会搬什么粒度」；只覆盖一种粒度的校验器，
在另一种粒度上会**静默地全部拒绝**（不是报错，是「什么都没发生」）。

### ❌ 批量隔离时忘了目标名会重名

**现象**：把 335 个重复副本搬进 `/90_待清理/重复副本/`，其中 **169 项**（62 个名字）
在目标目录里撞名 —— 最多的一个名字有 5 份（`sd3_medium_incl_clips_t5xxlfp8.safetensors`）。
`ondup:'skip'` 不覆盖，直接报 `errno:-8`，那批文件**留在原地，空间没释放**。

**✅**：spec 生成时就把**目标名去重**（同名第二个起加 `__2`/`__3`），并且去重要**按小写比较**
—— 网盘文件名大小写不敏感，`instantID_x` 与 `instantid_x` 是同名（这俩撞名时报的也是 -8）。

### ❌ 幂等回查只查第 1 页 → 已搬好的文件被误报成失败

**现象**：搬完重跑，335 项里报 85 项失败，实际**全部已在目标**。查 `file_list` 才知道
**每页只有 10 条**，目标目录有 300+ 项时，第 1 页里根本没有那个名字 → 「目标已在」永远判否。

**✅**：回查必须**翻页拉全量**（且**按目录缓存**——逐项翻页会把 335 项变成几千次调用，
实测跑 10 分钟没完）；**目标目录内容每批都在变，缓存必须每批失效**，
否则用的是搬之前的旧列表，还是会误判。

### ❌ MCP 返回的 JSON 末尾少一个 `}`，被幂等回查掩盖成「全绿」

**现象**：批量搬 335 个文件，脚本报「335 成功、0 失败」—— 但**一次都没真正搬出去**。
**原因**（两层）：
1. MCP 的 `file_move` 返回文本**末尾少一个 `}`**（花括号 2 vs 1），
   `JSON.parse` 直接失败 → `info[]` 永远是空 → 每项都判「失败」。
2. 失败后走幂等回查「源不在 + 目标已在 → 已完成」—— 而目标确实在
   （上一轮搬过）→ 于是**全部变成「已就位」**。
   **幂等回查把「调用被拒」和「已经搬完」混成了一件事。**

**✅**：解析要**宽松**（按花括号配对扫出第一个 JSON 对象，缺右括号就补齐再 parse）；
调用层被拒（`params error` / `errno:2`）要**硬失败**，不能落到幂等回查那条路上。
**教训**：「全绿」要先确认**调用真的发出去了** —— 用一个真会搬的东西做功能测试，
别拿「已经在目标」当成功判据。

### ❌ MCP 的 `filelist` 参数是 JSON **字符串**，不是数组

**现象**：`file_move` 传数组 → 返回 `params error: (response.body:{"errno":2,...})`，
所有项报 `no-info`；改成 `JSON.stringify(filelist)` 立刻正常。
（工具描述写「json串数组」，示例却给的是数组 —— **以服务端报为准**。）

**✅**：参数类型照 MCP schema 来；不确定时**两种都试一遍**，看哪个不报 params error。

### ❌ 批量里一个超大目录，整批都被拖垮

**现象**：3 个目录一批搬（218GB / 228GB / 744GB），**3 个全失败**；
逐个提交后，两个小的都成了，只有最大的那个单独失败。
**原因**：批量里只要有一个超大目录，整批被服务端拒（`errno:12` + `info` 为空），
同批的小目录跟着一起完蛋。

**✅**：**目录级移动逐个提交**（`async=1` 时步长=1）；文件级小批量照旧。

### ❌ 扫描不剪掉已消失的路径 → 体量被重复计算

**现象**：隔离搬走 335 个文件（1.35 TB）后重扫，库里体量从 **7.06 TB 涨到 8.45 TB**
—— 被搬走的文件在库里留下了**旧路径 + 新路径**两行，体量算了两遍。

**✅**：扫描时，**对每个确实列到的目录**，删掉「声称是它子项、但实际不在列表里」的行；
**列举失败时绝不删**（一次网络抖动就会抹掉整棵子树的记录）。

### ❌ Git Bash 下不关路径转换

**现象**：`--path=/课程` 被 MSYS 转成 Git 安装目录下的 `课程`（如 `Program Files/Git/课程`），接口回 `errno -7`；
`ROOTS="/课程|/我的资源"` 整个扫描扫成 0 字节。

**✅**：跑脚本前 `export MSYS2_ARG_CONV_EXCL='*' MSYS_NO_PATHCONV=1`。

### ❌ 并发开多个 `mcp-remote`

**现象**：`mcp-remote: the connection to the remote server dropped before this could be answered`。
**✅**：同一时刻只开一个桥。
