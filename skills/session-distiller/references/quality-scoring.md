## 六、得分计算

```
总分 = (验证性得分/3 × 25%)
     + (具体性得分/3 × 25%)
     + (完整性得分/3 × 20%)
     + (反例得分/3 × 20%)
     + (可执行性得分/3 × 10%)

得分判定:
  4.5 - 5.0 🟢 优秀
  4.0 - 4.4 🟡 可接受
  3.0 - 3.9 🟠 需改进
  0.0 - 2.9 🔴 必须返工

得分 ≥ 4.0 才可交付。
```

## 七、常见问题与处理

### 7.1 得分 < 4.0 怎么办?

```
处理流程:
  1. 定位得分最低的检查项
  2. 针对性改进:
     - 验证性低 → 添加验证方法
     - 具体性低 → 补充具体路径/命令
     - 完整性低 → 补充边界条件
     - 反例得分低 → 添加失败案例
     - 可执行性低 → 补充前置条件
  3. 重新检查
  4. 重复直到得分 ≥ 4.0
```

### 7.2 某条规则确实无法验证怎么办?

```
处理方式:
  1. 标注为"建议"而非"铁律"
  2. 补充说明: "此建议基于经验,无法机器验证"
  3. 提供人工检查项 (如: "人工检查: 是否有注释?")
```

### 7.3 缺少失败案例怎么办?

```
处理方式:
  1. 如果是新方法,无失败案例 → 标注"待实战验证"
  2. 如果是已有方法 → 搜索历史会话/bug 记录
  3. 如果确实无案例 → 构造边界失效场景
     - "假设场景 X,方法可能失效,原因是 Y"
```
