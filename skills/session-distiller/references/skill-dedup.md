# 技能去重检查详细指南

> 确保蒸馏会话后不会产生重复技能，避免项目技能库混乱。
>
> **核心原则**: 内容优先 — 先分析会话定位，再针对性匹配已有技能。
>
> **与 SKILL.md 的对应**: SKILL.md 的 Step 2「生成主题指纹并扫已有技能」只留指针，
> 四步流程（分析会话定位 → 带指纹扫描 → 针对性匹配 → 决策路径）、相似度算法与合并策略以本文为准。
> **扫描范围默认锁在项目内**；全局库与跨项目位置只有用户明确要求时才看。

---

## 零、正确的去重流程 (内容优先)

> **为什么必须"内容优先"?**
> 因为只有先理解会话解决的是什么问题，才能知道要去匹配哪个已有技能。
> 盲目扫描所有技能既浪费算力又可能误判。

### 0.1 内容优先的去重流程

```
Step 1 — 分析会话内容定位 (先做这个!)
  ├─ 提取会话核心主题
  │   └─ 例: "反复道歉治理"
  ├─ 识别解决的问题
  │   └─ 例: "Agent 反复道歉但无效,缺少失败分析"
  ├─ 提炼方法论关键词
  │   └─ 例: ["失败计数", "切换 agent", "阻塞报告"]
  └─ 生成"会话主题指纹"

Step 2 — 带着主题指纹去扫描已有技能（**默认只扫项目内**）
  ├─ 扫描范围 = 项目根下的技能与规则，别无其它:
  │     skills/ · .agents/skills/ · AGENTS.md · 项目自己的 rules 目录
  ├─ 不扫: ~/.agents/skills/（用户全局库）· 其它项目 · 宿主自带技能目录
  │     ⇒ 这些只有用户明确要求（"也看看全局"）时才扫，且产出里标注"已超出项目范围（用户要求）"
  ├─ 用核心主题过滤 → 找到候选技能
  │   └─ 例: 项目内包含"道歉"关键词的技能
  └─ 对候选技能计算相似度

Step 3 — 针对性匹配
  ├─ 匹配核心主题 → 找到候选技能
  ├─ 匹配解决的问题 → 缩小范围
  └─ 匹配方法论关键词 → 确认相似度

Step 4 — 决策路径
  ├─ 无匹配 → 继续蒸馏 → 生成新技能
  ├─ 有匹配 + 有增量价值 → 更新已有技能
  └─ 有匹配 + 无增量价值 → 跳过,告知用户
```

### 0.2 为什么旧流程是错的

```
❌ 旧流程 (先扫描技能):
  1. 扫描所有已有技能 → 100+ 个技能
  2. 对每个技能计算相似度 → 浪费算力
  3. 盲目匹配 → 可能误判

问题:
  - 不知道要匹配什么,盲目计算所有技能的相似度
  - 项目有 100 个技能,就要做 100 次相似度计算
  - 可能匹配到不相关的技能,产生误判

✅ 新流程 (内容优先):
  1. 先分析会话 → 提取"反复道歉治理"主题
  2. 带着主题去扫描 → 只匹配包含"道歉"的技能
  3. 精准定位 → 发现已有 apology-discipline
  4. 增量判断 → 决定合并还是跳过

优势:
  - 明确知道要匹配什么
  - 只对相关技能做相似度计算
  - 精准定位,不会误判
```

## 一、为什么去重至关重要

### 1.1 真实问题场景

```
会话 1: "反复道歉" → 蒸馏出 "apology-discipline" 技能
会话 2: "反复道歉" → 又蒸馏出 "repeat-apology" 技能
会话 3: "反复道歉" → 再蒸馏出 "agent-apology-fix" 技能

结果:
  - 同一个问题有 3 个技能
  - 铁律重复定义
  - 用户不知道用哪个
  - 维护成本 × 3
```

### 1.2 去重的价值

```
无去重:
  - 技能数量爆炸
  - 相似技能混淆
  - 维护成本线性增长

有去重:
  - 技能数量收敛
  - 一个问题一个技能
  - 增量更新,质量提升
```

## 二、相似度判定算法

### 2.1 四维相似度检查

```
维度 1: 核心主题相似度
  ├─ 提取技能的 name + description
  ├─ 分词 + 去停用词
  ├─ 计算关键词重合度
  └─ 公式: 重合关键词数 / max(关键词数)

维度 2: 触发词相似度
  ├─ 提取 triggers 列表
  ├─ 计算重叠比例
  └─ 公式: 重叠触发词数 / max(触发词数)

维度 3: 解决的问题相似度
  ├─ 提取技能解决的问题域
  ├─ 判定是否解决同一问题
  └─ 布尔值: 是/否

维度 4: 方法论相似度
  ├─ 提取铁律 (MUST/NEVER)
  ├─ 计算铁律重合度
  └─ 公式: 重合铁律数 / max(铁律数)
```

### 2.2 相似度阈值

```
综合相似度计算:
  综合相似度 = (主题相似度 × 0.4)
             + (触发词相似度 × 0.2)
             + (问题相似度 × 0.3)
             + (方法论相似度 × 0.1)

判定标准:
  ├─ 综合相似度 ≥ 80% → 高度相似 → 必须合并
  ├─ 综合相似度 50%-80% → 中度相似 → 建议合并
  └─ 综合相似度 < 50% → 低相似 → 可新建
```

## 三、合并策略详解

### 3.1 三种决策路径

| 场景 | 条件 | 决策 | 动作 |
|------|------|------|------|
| **新建** | 无相似技能 或 相似度 < 50% | 创建新技能 | 正常蒸馏流程 |
| **合并** | 有相似技能 + 新会话有增量价值 | 更新已有技能 | 补充增量内容 |
| **跳过** | 有相似技能 + 无增量价值 | 跳过蒸馏 | 告知用户"已有相似技能" |

### 3.2 增量价值判定

```
新会话有以下之一 → 有增量价值:
  1. 新的铁律 (MUST/NEVER)
  2. 新的反例 (失败案例)
  3. 新的方法论 (验证方法)
  4. 更详细的流程 (Step 细化)
  5. 补充边界条件 (适用/不适用场景)

全无 → 无增量价值
```

### 3.3 合并执行协议

```
发现相似技能 + 有增量价值 → 执行合并:

Step 1 — 读取已有技能
  └─ Read {skill-name}/SKILL.md

Step 2 — 识别增量内容
  ├─ 对比新会话提炼的铁律 vs 已有铁律
  ├─ 对比新会话的反例 vs 已有反例
  └─ 识别新增部分

Step 3 — 确定合并位置
  ├─ 新铁律 → 补充到 SKILL.md §N
  ├─ 新反例 → 补充到 references/traps.md
  ├─ 新方法论 → 补充到 references/methodology.md
  └─ 新流程 → 细化对应 Step

Step 4 — 执行合并
  └─ Edit 已有技能文件

Step 5 — 输出合并报告
  ├─ 合并了哪些内容
  ├─ 更新了哪些文件
  └─ 版本号升级建议
```
